WHAT THIS RUN FIXED
Fifteen real defects, each found by a failing test rather than by inspection. The
most serious:
- The AI toggle was a no-op at startup: the runtime defaulted to enabled while the
  persisted setting defaulted to disabled, so a fresh install could send user
  utterances to a remote model while the Settings switch displayed "off".
- open_app reported "Opening." for apps that were not installed or had no launcher,
  because AppLauncher's typed outcome was discarded.
- The confirmations toggle drove only its own switch and gated nothing.
- DiagnosticsRecorder echoed a typed password and card number verbatim; the redactor
  only matched assignment shapes, not "my password is X".
- Notification text could carry a full email body.
- A spoken transcript routed through the same pipeline gained no extra authority, and
  the voice collector leaked a coroutine that hung the test suite for 60s per case.

KNOWN GAPS
Listed in full under "Known gaps" in MILESTONES.md. The main one: DotTool.timeoutMs
is declared on every tool but never enforced, so a hung tool has no upper bound.

VERIFICATION LIMITS
JVM unit tests and Robolectric only. No device or emulator was available, so
notification delivery, exact-alarm timing, Compose rendering, PackageManager
resolution, SpeechRecognizer and WorkManager under doze remain unverified.

SECRETS
local-secrets.properties is gitignored and holds the provider key. The key is read
into BuildConfig at build time and appears in no tracked file. Note that the key does
ship inside a compiled APK — a distribution concern for any real release.
